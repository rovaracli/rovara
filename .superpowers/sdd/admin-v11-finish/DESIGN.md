# Task 1: explicit company spending-stop enrollment (M1 proposal)

Base: v0.5.3, 030a4b716beeb816f7a17eb4f960a6afa6727c39. No production implementation at M1.

## States and authority

`disabled -> ready -> enabled`; `enabled -> disabled`. Also allow `ready -> disabled` to abandon a review. No direct disabled-to-enabled transition. Bootstrap and upgrades continue to write disabled. Both disabled and ready retain the existing admission branch without modifying its outputs, writes or calculation. No new deployment switch, environment variable, IAM boundary, dependency or numeric policy default.

Only a live company owner may read enrollment/review results or perform a transition. Admin, project maintainer, member and auditor cannot. Read the canonical member, developer-org pointer, live sign-in identity and open org on every request; use the existing actor evidence reader, restricted to owner. Fence those same native values at commit. Never rely on caller.orgRole alone. A project grant cannot confer company owner authority.

## API and persisted keys

Use `/v1/app/org/task-stop-policy/enrollment`: GET returns `{state, revision}`; PUT accepts a strict body `{requestId, expectedRevision, state, reviewId?, expectedReviewDigest?}`. `state` is ready, enabled or disabled. Review fields are required for ready/enabled and forbidden for disabled. Caller supplies no org, actor, raw checks, calculation input, eligibility or task list.

POST `/v1/app/org/task-stop-policy/cutover-review`, strict `{requestId, expectedRevision}`, builds a review on the server while enrollment is disabled or ready. It does not itself change enrollment. Return `{reviewId, digest, revision, complete, capturedAt, expiresAt, tasks}`. GET/POST are browser-session routes using the existing CSRF/session router conventions. New code belongs in `org/task-stop-enrollment.ts` and `org/task-stop-cutover-review.ts`; only small dispatch wiring in developer-routes.ts. Shared schemas in a new browser-safe contract and a lazy UI API module.

Canonical policy key: `orgSettingsKey(orgId, "TASK_STOP_POLICY")`, entity `ORG_TASK_STOP_POLICY`. Each real transition increments its existing positive safe-integer revision, preserving policy, pending edits and seed provenance. Enrollment remains version 1; ready/enabled bind `reviewId`, `reviewDigest`, reviewing owner and review time. Reject malformed or missing enrollment/policy, overflow, stale revision and illegal state transitions.

Review key: new checked org-scoped helper for `{pk: orgScoped(orgId, "TASK_STOP_REVIEW"), sk: reviewId}`. Review ids are server-generated UUIDs. Store bounded immutable review content, digest, actor, original company revision and native source identities with a TTL; never serialize native conditions to the browser. Keep the same review when ready increments the company revision; enable verifies the review's base revision is exactly the ready revision minus one and the ready enrollment still names that review.

Request key: existing `agentRequestKey(orgId, developerId, requestId)` and `readRequest`/`commit`. Fingerprint the operation, checked org and complete body with canonicalJson. Same id/body returns the stored result without writes, including after disable. Same id/different body returns CONFIG_INVALID (the checklist's specified behavior). Replays require current owner authority before revealing a result. Recover ambiguous transaction outcomes by re-reading the receipt before reporting a conflict.

## Cutover review content and bounds

Enumerate checked org project catalog pages and each project's existing workspace-project index, resolve workspace task pointers and strongly re-read native task rows. Include agent-run tasks through the same native task pointers; deduplicate ids. Re-read each task's checked org before projecting any result. Never accept client-supplied task ids or silently skip malformed/cross-org native references. Bound enumeration to 100 projects, 500 workspaces and 25 active tasks, and total serialized review to 128 KiB. Exhaustion, repeated/foreign cursors, unreadable settings, unresolved model funding or over-budget transaction size refuses the review; partial results cannot set ready.

For every running/queued task call `captureTaskStopCutoverReview` with server-built identity and existing task/path bounds; it already calls `calculateTaskStop`. Capture native task/workspace/project lifecycle conditions and current funding evidence. Reuse proven exemption logic; customer limits remain independent and enforced. Return only taskId, project, current phase, effectiveStopMicrousd, current committed cap, binding scopes and a fixed outcome/reason. Classify as `refuse_next_admission` for zero stop, `stop_at_next_admission` where a replacement window cannot be admitted, `retain_current_window` for already admitted work, or `exempt` with verified source evidence. No task titles, instructions, source metadata, free-form errors or secret values. Show both running and queued tasks, including unaffected ones, so absence of impact has a positive control. Invalid source data aborts rather than presenting a safe verdict.

Current accepted windows are immutable: enabling is not a cancellation or retroactive cap rewrite. The review must explicitly explain that effects apply at the next admission/mint according to existing enforcement, not promise that already admitted work is immediately stopped. Use the calculator's existing semantics; its ceiling is an approval cap and does not clamp an ordinary unapproved estimate. Do not introduce a second calculation.

**Inventory limitation for controller review:** the existing workspace-project index is eventually consistent and cannot certify absence of concurrently created work. Label the report as an as-of preview, not a rollout certificate. Enable re-enumerates and compares the projected inventory and all economic/lifecycle sources; any observed change requires a fresh review. Work appearing after the preview is governed by the canonical enabled admission branch on its next admission. No assertion that a GSI query is serializable. If the controller requires an exhaustive instant cutover guarantee instead, a native org work-inventory generation and coordinated writers are required and need a separate design; do not silently add this to other lanes.

Review expires after 5 minutes (server clock; reject future capture times). Ready requires the persisted complete matching review captured by this owner. Enable requires it again, plus a recent interactive sign-in: load the same caller session from the sign-in table and use `isFreshSignIn`; reject missing/malformed/future authTime, wrong person, expired/revoked session, and identities invalidated by sessionsEndedAt with REAUTH_REQUIRED. Refresh timestamps never count. Fence the live session row at commit. Five minutes is an implementation proposal, not a new platform authentication duration.

## Transactions and audit

Review capture: review Put + expiring request receipt + current owner/identity/org/company/source conditions. Ready/enable: policy Put + immutable review ConditionCheck + owner/member/pointer/identity/org conditions + source task/project/agent/guardrail/seed conditions + enable session condition + audit pending Put + request receipt. Disable: policy Put + owner/member/pointer/identity/org conditions + audit pending Put + request receipt. Deduplicate by table/pk/sk and merge compatible conditions, including conditions for the company into its Put; reject contradictory snapshots. Count before sending: maximum 100 actions and 4 MiB, maximum 400 KiB per item. A race yields CHANGE_STALE for policy/review/economic drift, FORBIDDEN for authority loss, REAUTH_REQUIRED for sign-in loss. No partial audit, receipt or policy update.

Proposed new audit actions: `spending.enrollment_reviewed`, `spending.enrollment_changed`. Add contract allow-lists, builders and contract samples at M2. Facts contain requestId, reviewId/digest, before/after state, revision, task count and impact counts only. Actor is the current member, target is the checked org; no user text or raw checks. Audit must be configured or return AUDIT_UNAVAILABLE. Audit outbox is transactional; queue outage preserves the pending event and successful outcome.
